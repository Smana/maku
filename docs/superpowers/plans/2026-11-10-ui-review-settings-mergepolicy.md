# Settings review, MergePolicy first: implementation plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** the settings pages read a repository's merge classes as its `MergePolicy` resource (status, authority, conditions said once), each class card leads with its intent, and a filter narrows the repository table and the class cards.

**Architecture:** two additive Go changes (a class `description` in `config.Class` and the policy file's `ClassPolicy`; the MergePolicy's stored status attached to the evidence report the settings API serves), then the web pages rebuilt on them: one header per repository page, a quieter class card, the editor's *What it is for* group, a filter module, three preview repositories.

**Tech Stack:** Go 1.x (controller-runtime, kubebuilder markers, stdlib `testing`), TypeScript DOM, vitest, esbuild preview.

**Spec:** `docs/superpowers/specs/2026-11-10-ui-review-design.md`, Part 1, **§1.6 to §1.8** (they bind over §1.0 to §1.5 where they differ). Background for the resources: `docs/superpowers/specs/2026-11-09-factory-resources-design.md` D4, D9, D10.

**Branch:** `ui/review-settings` (continues PR 1; base for this plan `93dc52f7`).

## Global Constraints

- `task check` exits 0 before the last commit; `task ui:build` output in `internal/humanapi/ui/dist/` is committed.
- Go: stdlib `testing`, table-driven `t.Run`, exported symbols carry doc comments, errors wrap with `%w`, every `.go` file starts `// SPDX-License-Identifier: Apache-2.0`. Lint only through `task lint`.
- Goldens only for rendered artifacts, rewritten only with the package's `-update-golden` flag.
- CRDs and deepcopy are generated: run `task crd:gen`; never hand-edit `config/crd/` or the chart's CRD copy.
- A status is always a word plus a colour, never a colour alone.
- No emoji in UI copy. Motion: opacity and transform only, none under `prefers-reduced-motion`.
- Headings: h2 per page section, h3 per class card or editor group; no level skipped.
- Under 720 px nothing scrolls sideways.
- Never run a command with `HOME=...` or `env -i`. Commits carry no `Co-Authored-By` line. Never push.
- `description`: plain text, at most **280** characters (runes), optional.
- Filter: case-insensitive, in the browser, count text `"<shown> of <total>"`, query kept in `?q=`, `/` focuses it (not while typing in a field).

## Rulings made while planning

- **R1 (status source).** §1.6 says "what `statuswriter.Desired` computes". Recomputing it per request needs every Desired input on every replica. The leader already writes exactly that into `MergePolicy.status`, and every replica's manager cache holds the object. The report therefore carries the **stored** status read from the cached client (`mgr.GetClient()`), which is literally what `kubectl get mergepolicy` shows, with no API-server round trip. Cost if wrong: a follower lags the leader's write by one watch event.
- **R2 (repository authority).** "Edits produce the MergePolicy manifest only" applies under authority `central`. Under authority `repository` (stage 4) the repository file decides, so the editor keeps the file path and the header says the file decides. This is today's `centralManifest` rule; only the wording changes.
- **R3 (promotion on a MergePolicy).** No new promotion flow. A shadow class served from a MergePolicy says how to promote ("set `live: true` on this class in the MergePolicy and merge the change") and offers the editor; the factory's file proposal stays for repository-file classes.

```ts
// case-insensitive, against every whitespace-separated word of the query; hidden items get the

export function filterField<T extends HTMLElement>(opts: {

}): { box: HTMLElement; apply: () => void };
```
