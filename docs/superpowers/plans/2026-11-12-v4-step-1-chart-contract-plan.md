# v4 rollout step 1, the chart contract: implementation plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** the umbrella chart gets a contract a production install can rely on:
- the CRDs ship in their own `agent-factory-crds` chart, which Helm, Flux and Argo CD upgrade;
- the demo leaves the chart's defaults for `values-demo.yaml`;
- a `values.schema.json` rejects unknown and malformed values;
- the umbrella and the CRD chart are published and signed like `maku` and `maku-factory`.

Every existing install keeps working (D25). The demo renders the same objects through `-f values-demo.yaml`. The `maku` and `maku-factory` charts, which ANR consumes, are unchanged apart from `kubeVersion` and keep their `crds/`.

**Architecture:** `task crd:gen` gains one more destination, `charts/agent-factory-crds/templates/`. Each CRD there gets `helm.sh/resource-policy: keep` added by a small template wrapper, so the generated YAML stays byte-identical to `config/crd`. The umbrella's `values.yaml` becomes the production skeleton. `profile: production` is accepted by the schema and fails at render with a message naming the rollout steps that bring its seams. The demo's current defaults move verbatim into `values-demo.yaml`.

**Tech Stack:** Helm 3.14+ (JSON Schema draft-07 for `values.schema.json`), bash render tests (`yq`, `openssl`), kind and k3d install tests, the GitHub Actions release and pre-release jobs (cosign).

**Spec:** `docs/superpowers/specs/2026-11-12-v4-production-path-design.md`: D13 (chart contract), D25 (rollout), D26 (support floor).

**Branch:** `feat/v4-chart-contract`, from `origin/main`.

## Global Constraints

- **No v4.** This step ships as a v0.4x minor. No tag, release or chart version 4.x is created; the v4.0.0 cut waits for the owner's explicit go.
- **Additive (D25).**
  - The demo renders exactly what it renders today, through `-f values-demo.yaml` (a golden diff proves it). `--set profile=demo` alone fails with a message naming the file (PR5).
  - `charts/maku/crds/` and `charts/maku-factory/crds/` stay, so ANR's HelmRelease (`crds: CreateReplace`) and its `crd-rooms.yaml` are untouched.
- **One CRD source.** `config/crd/` is generated by controller-gen. Every chart copy is produced by `task crd:gen`, and `task crd:check` fails on any drift.
- **The support floor is in the charts.** `kubeVersion: ">=1.30.0-0"` in all four `Chart.yaml` files (D26).
- `task check` before the last commit. Never `HOME=…` or `env -i`. No attribution lines. Conventional commits in English.

## Rulings made while planning

- **PR1 (CRDs in templates, not `crds/`).** A CRD in `templates/` is upgraded by every tool, but deleted on uninstall. `helm.sh/resource-policy: keep` on each CRD prevents that, so uninstalling the CRD chart never deletes Rooms or Tasks.
- **PR2 (adopting existing CRDs).** On a cluster where the CRDs came from a subchart's `crds/` (gcp-0, aws-0, any demo), Helm refuses to install the CRD chart: "exists and cannot be imported into the current release". The CRD chart's README and `docs/upgrading.md` give the three `kubectl label/annotate` commands that hand the CRDs to the release (`app.kubernetes.io/managed-by=Helm`, `meta.helm.sh/release-name`, `meta.helm.sh/release-namespace`). The k3d test proves them (Task 5). ANR's switch is its own PR, after this release.
- **PR3 (the skeleton fails closed, nothing more).** Production seams do not exist yet (steps 2–6), so `profile: production` renders nothing and fails with: `profile production: its seams arrive in rollout steps 2 to 6 (docs/superpowers/specs/2026-11-12-v4-production-path-design.md); use -f values-demo.yaml for the demo`. The schema already lists `production` so the contract's shape is fixed now.
- **PR5 (`--set profile=demo` alone fails closed).** See Task 2 Step 3. This is the one user-visible change. It is named in the release notes and in `docs/upgrading.md`, and it is allowed in a 0.x minor (D13's no-breaking-change rule starts at v4.0.0).
- **PR4 (the schema covers the umbrella's own keys).** `maku` and `maku-factory` are typed `object` with free properties in this step. The subcharts get their own schemas when their values change in steps 2–6. Unknown top-level umbrella keys are rejected (`additionalProperties: false`), which catches typos like `postgress:`.

### Task 2: the demo moves to `values-demo.yaml`

**Files:**
- Create: `charts/agent-factory/values-demo.yaml`
- Modify: `charts/agent-factory/values.yaml`, `charts/agent-factory/templates/_helpers.tpl`, `charts/agent-factory/tests/render.sh`

- [ ] **Step 1: golden first.** Before changing anything, render today's demo (`render.sh`'s `args`) to `$tmp/before.yaml`. The test then renders `-f values-demo.yaml` with the same `--set` image and secret flags and asserts the two are identical (`diff`), so the move is proved byte-for-byte. Expected FAIL: the file doesn't exist.
- [ ] **Step 2: the move.**
  - `values-demo.yaml` gets `profile: demo` and every demo default from today's `values.yaml`, with its comments: `demo:`, the `maku:` and `maku-factory:` blocks, `tls`, `postgres`, `networkPolicies.plain`.
  - `values.yaml` keeps only `profile: ""`, `clusterDomain: cluster.local` and empty `maku: {enabled: true}` / `maku-factory: {enabled: true}`. A header explains that the defaults are production-safe and that the demo is `-f values-demo.yaml`.
- [ ] **Step 3: `--set profile=demo` alone fails closed (PR5).** A subchart reads only the values Helm hands it, so no parent helper can bring back the demo's `maku:` and `maku-factory:` defaults. Without `values-demo.yaml` the render would be half a demo: Cilium policies on, a cert-manager issuer expected, a sandboxed RuntimeClass required. `afumbrella.profile` detects this with a marker, `demoValues: true`, which is set only in `values-demo.yaml`. When `profile` is `demo` and the marker is missing, it fails with `profile demo needs -f values-demo.yaml (the demo's defaults moved there in v0.4x)`. The schema allows `demoValues`. Update every caller in this task to pass `-f values-demo.yaml`: `install.sh`, `intake.sh`, `hack/demo/up.sh`, the `chart:check` lint line, and `render.sh`'s `args`.
- [ ] **Step 4:** `bash charts/agent-factory/tests/render.sh`: PASS (the golden). Then `task chart:check`: PASS.
- [ ] **Step 5: commit** `refactor(charts): the demo's defaults move to values-demo.yaml`.

### Task 3: `values.schema.json` and the production gate

**Files:**
- Create: `charts/agent-factory/values.schema.json`, `charts/agent-factory/tests/schema.sh`
- Modify: `charts/agent-factory/templates/_helpers.tpl`, `taskfile.yaml`

- [ ] **Step 1: write failing negative tests in `schema.sh`.** Each case runs `helm template` and must fail with the named message:
  - `--set postgress.storage=1Gi`: "additional properties 'postgress' not allowed";
  - `--set profile=prod`: the enum message;
  - `--set tls.days=0`: minimum 1;
  - `--set postgres.storage=lots`: pattern;
  - `--set profile=production`: the PR3 message.

  Positive: `-f values-demo.yaml` with the image and secret flags renders. Run it; expected FAIL.
- [ ] **Step 2: the schema** (draft-07):
  - `profile` is an enum of `""`, `demo` and `production`;
  - `clusterDomain` is a hostname pattern;
  - `demo.model` and `demo.githubApp` are typed strings;
  - `tls.days` is an integer ≥1, and `tls.caName` a string;
  - `postgres.image` must match a pattern with `@sha256:`, `postgres.storage` the quantity pattern `^[0-9]+(Mi|Gi|Ti)$`, `storageClassName` is a string, and `resources` an object;
  - `networkPolicies.plain` is a boolean;
  - `maku` and `maku-factory` are objects with free properties (PR4);
  - `additionalProperties: false` at the top level.
- [ ] **Step 3: the gate.** `afumbrella.profile` fails with the PR3 message for `production`. The unset-profile message becomes: `profile is required: demo (-f values-demo.yaml), or production (rollout steps 2 to 6)`.
- [ ] **Step 4:** add `bash charts/agent-factory/tests/schema.sh` to `chart:check`. Run `task chart:check`: PASS.
- [ ] **Step 5: commit** `feat(charts): a values schema, and profile production fails closed`.
