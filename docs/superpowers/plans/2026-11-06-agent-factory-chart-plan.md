# The umbrella chart with `profile: demo`: implementation plan (plan B of the factory on a laptop)

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** `helm install demo charts/agent-factory --set profile=demo …` brings up Maku's broker, run-controller and factory on a plain kind or k3d cluster: no Cilium, no cert-manager, no CNPG, no gVisor.

**Architecture:** A new chart `charts/agent-factory` depends on `charts/maku` and `charts/maku-factory` by `file://` and adds what a plain cluster lacks: a Postgres StatefulSet with its roles, TLS for the broker generated by Helm, the Secrets a demo needs, and the demo's factory config. Two switches go into the existing charts and the run-controller so they run without Cilium and without the OIDC and CA mounts.

**Tech Stack:** Helm 3 (`genCA`, `genSignedCert`, `lookup`), Go (run-controller), bash render tests with `yq`.

**Spec:** `docs/superpowers/specs/2026-11-06-factory-on-a-laptop-design.md` (Q14, Q19, Q20, Q22). Builds on plan A (`docs/superpowers/plans/2026-11-06-factory-demo-mode-plan.md`): the factory's `demo: true`, `merge.gateStatus`, `merge.policyBot: false`, and the demo's `agent-git` writer.

## Global Constraints

- `task check` exits 0 before every commit; lint via `task lint`. Conventional commits, no trailers.
- Production is unchanged when the new keys are left at their defaults: `networkPolicies.enabled` defaults to true, the run-controller's `networkPolicy` defaults to `cilium`, and the factory chart's mounts stay required unless `demo` is set.
- Q19: production differs from the demo only by values. Q20: the chart is `charts/agent-factory` in this repository.
- Q22: no Cilium, cert-manager, CNPG or gVisor; plain runc with the room's "not sandboxed" banner (`runController.allowUnsandboxed: true`, `runtimeClassName: ""`).
- Images are pinned by digest as today (`^[A-Za-z0-9_.-]+@sha256:[0-9a-f]+$`), except under the existing `e2e.unpinnedImages` switch.

### Task 3: The umbrella chart, its TLS and its database

**Files:**
- Create: `charts/agent-factory/Chart.yaml` (dependencies `maku` and `maku-factory` from `file://../maku` and `file://../maku-factory`, each with `condition`), `values.yaml`, `templates/_helpers.tpl`, `templates/tls.yaml`, `templates/postgres.yaml`, `templates/db-secrets.yaml`, `templates/NOTES.txt`, `tests/render.sh`, `README.md`
- Modify: `taskfile.yaml` (`chart:check`: `helm dependency build charts/agent-factory`, `helm lint --strict`, `bash charts/agent-factory/tests/render.sh`), `.gitignore` (`charts/agent-factory/charts/`)

Contents:
- `tls.yaml`: with `lookup`, reuse an existing `room-broker-ca` Secret; otherwise `genCA "maku-demo-ca" 3650` and `genSignedCert` for `room-broker.<ns>.svc` and `room-broker.<ns>.svc.<clusterDomain>`. Render three Secrets: `room-broker-tls` (type `kubernetes.io/tls`), `room-broker-ca` (key `ca.crt`), and the factory's broker CA Secret (name from `maku-factory.brokerCASecret`, key `ca.crt`, the same CA). Annotate `helm.sh/resource-policy: keep` so an upgrade never rotates them.
- `postgres.yaml`: a single-replica StatefulSet `rooms-db` (`postgres:17` by digest, a 1Gi PVC on the default StorageClass, which kind and k3d both provide), a Service `rooms-db`, an init ConfigMap creating roles `rooms_owner`, `rooms_broker`, `rooms_retention` and database `rooms` owned by `rooms_owner`, with `GRANT CREATE, USAGE ON SCHEMA public TO rooms_owner` (PG ≥ 15 no longer grants `public` CREATE). Probes, requests and limits, and the restricted security context, as the other charts.
- `db-secrets.yaml`: passwords from `lookup` or `randAlphaNum 32`, `keep`; Secrets `rooms-broker-dsn` and `rooms-owner-dsn` with key `uri` = `postgresql://<user>:<pw>@rooms-db.<ns>.svc:5432/rooms?sslmode=disable`. Verify the broker's store accepts `sslmode=disable` (`internal/store/store.go:63`); if it refuses, add an explicit allowance gated on the DSN host being in-cluster, in its own commit with a test.

- [ ] Step 1: `tests/render.sh` with the `charts/maku/tests/render.sh` helpers (`check`, `ykind`, `ynone`): the default render contains the three TLS Secrets with matching CA, the StatefulSet with probes and limits, both DSN Secrets with `sslmode=disable`, and no CiliumNetworkPolicy, Certificate or Issuer when `profile=demo`. ### Task 4: `profile: demo`

**Files:**
- Modify: `charts/agent-factory/values.yaml`, `templates/_helpers.tpl`, `templates/secrets.yaml` (new), `tests/render.sh`

`profile: demo` sets, and the render test pins:
- `maku`: `networkPolicies.enabled: false`; `broker.human.mode: local`; `broker.roomTools.enabled: false`; `broker.runIssuer.mode: tokenreview`; `broker.systemIssuer` in `tokenreview` mode with the factory's ServiceAccount as `system:factory`; `broker.factoryInsecure: true`; `broker.database` the two DSN Secrets; `broker.tls.issuerRef.name: ""`; `runController.runtimeClassName: ""`, `allowUnsandboxed: true`, `createRuntimeClass: false`; `runs` group `maku.ogenki.io`.
- `maku-factory`: `demo: true`; `replicas: 1`; `brokerCASecret` the umbrella's CA Secret; `config`: `demo: true`, `broker.url` the broker's `https://…:8443` with `caFile` the mounted CA, `broker.tokenFile` the projected token, `runs` the portable kind, `merge.gateStatus: true`, `merge.policyBot: false`, `github` files for one App with the merger files pointing at the same App, and `repositories` from `.Values.demo.repositories` (one entry, `factory/ready` trigger, one class from `.Values.demo.class`, default `docs-links` in shadow, plus `revert` in shadow). Every class the profile renders carries an explicit `allowedFiles` (for `docs-links` and `revert`, copy the built-in shape's), because plan A refuses `merge.policyBot: false` when a live class has none.
- `secrets.yaml`: `agent-model` in the runs namespace from `.Values.demo.model.{baseURL,name,apiKey}` or an `existingSecret`; `agent-factory-github` from `.Values.demo.githubApp.{id,privateKey}` or an `existingSecret`. Neither is rendered when its `existingSecret` is set. `agent-git` is not rendered: the factory writes it.
- An unset `profile` (production) renders none of the above and fails with a message naming what production must supply (`profile is required: demo, or production values (stage 2)`), until stage 2 adds production.

- [ ] Step 1: render rows for each bullet, and for `profile` unset failing. Step 2: run, fail. Step 3: implement. Step 4: `task chart:check`. Step 5: commit `feat(chart): profile: demo`.

### Amendments carried from plan A's final review

- The broker's `:8443` is always TLS, so the demo reaches it over `https` with the Helm-generated CA (Task 3), not the `http://` plan A allows. Task 4 also amends the design's Q22 line in `docs/superpowers/specs/2026-11-06-factory-on-a-laptop-design.md` ("plain HTTP inside the cluster") to say the broker keeps TLS with a CA the chart generates. Plan A's `http` and empty-`caFile` relaxations stay; whether to remove them is decided once Task 5 proves the install.
- The App's run token has no `statuses: write`; the merger connection posts the gate's status. Nothing in this chart changes that.
