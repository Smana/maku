# Install Secrets

Every credential and id an install reads is a Kubernetes Secret, named by a value and holding
documented keys. This page lists them all. The same list is data in `internal/install/secrets.go`,
and three things read it:

- this table, regenerated by `task chart:seams`;
- the umbrella chart's ExternalSecrets ([below](#externalsecrets));
- the components' start-up checks.

A component whose Secret or key is missing refuses to start, and names the seam:

```
brokerOIDC: Secret broker.oidc.existingSecret key web-client-id is missing or empty (docs/install-secrets.md)
```

The message names the Secret by its default name, or by the value that names it when there is no
default.

## The Secrets

The value is the key of the chart named after it. In the umbrella chart, prefix it with the
subchart's name (`maku.`, `maku-factory.`, `maku-gateway.`). The namespace is the release's, or
the runs' (`maku.runs.namespace`).

Some installs write a Secret for you:

- the bundled Postgres (`postgres.enabled`, the demo) writes the three DSNs and its passwords;
- the umbrella writes the broker's TLS pair and both CAs;
- the demo's `demo.model` and `demo.githubApp` values write the runs' model and the factory App;
- the factory writes the runs' git tokens.

Bring every other one yourself, by hand or with an ExternalSecret.

## ExternalSecrets

The umbrella chart can render an [External Secrets Operator](https://external-secrets.io) (ESO 0.17
or later) `ExternalSecret` for each Secret you list. It never renders a `SecretStore`: name one you
run already.

```yaml
externalSecrets:
  enabled: true
  apiVersion: external-secrets.io/v1
  storeRef: {kind: ClusterSecretStore, name: platform-secrets}   # or kind: SecretStore
  refreshInterval: 1h
  secrets:
    <seam id>:                       # a row of the table above
      data: [{secretKey: <key>, remoteRef: {key: <path>, property: <field>}}]
      # or dataFrom: [{extract: {key: <path>}}]
      template: {...}                # optional: ESO's target.template, passed through
      refreshInterval: 24h           # optional: this one's own
```

Each `ExternalSecret` takes its seam's resolved Secret name: the value that names it, else its
default. The subcharts therefore read the same name as without ESO. The target has
`creationPolicy: Owner` and `deletionPolicy: Retain`. A model provider of the gateway is listed as
`gatewayProvider.<name>`, and its Secret is `maku-gateway.providers.<name>.existingSecret`.

The render fails, naming the seam, in these cases:

- `enabled` is set with no `storeRef.name`;
- an id is not in the table;
- an entry has neither `data` nor `dataFrom`;
- a required key is produced by no `data` entry and by no `template.data` key. A `dataFrom` is
  trusted as it is: check its keys yourself;
- the install already writes that Secret: the bundled Postgres (`postgres.enabled`), the
  umbrella's TLS, the demo's `demo.model` or `demo.githubApp`, or the factory's git tokens. Two
  writers of one Secret would fight over it.

### OpenBao (KV v2)

```yaml
externalSecrets:
  enabled: true
  storeRef: {kind: SecretStore, name: agents-secrets}
  secrets:
    brokerOIDC:
      data:
        - {secretKey: web-client-id, remoteRef: {key: maku/oidc, property: web-client-id}}
        - {secretKey: cli-client-id, remoteRef: {key: maku/oidc, property: cli-client-id}}
    factoryApp:
      dataFrom:
        - extract: {key: maku/factory-app}     # holds app_id and private_key
```

### A DSN assembled from CNPG's role Secret

CloudNativePG writes each managed role's `username` and `password`. ESO's template assembles the
broker's `uri` from them, here read back through a store over the database's namespace:

```yaml
externalSecrets:
  enabled: true
  storeRef: {kind: ClusterSecretStore, name: cnpg-roles}
  secrets:
    databaseBroker:
      data:
        - {secretKey: username, remoteRef: {key: rooms-cnpg-role-rooms-broker, property: username}}
        - {secretKey: password, remoteRef: {key: rooms-cnpg-role-rooms-broker, property: password}}
      template:
        data:
          uri: "postgresql://{{ .username }}:{{ .password }}@rooms-rw.db.svc:5432/rooms?sslmode=verify-full&sslrootcert=/etc/room-broker/db-ca/ca.crt"
```

The same shape serves `databaseOwner` and `databaseRetention`, with their roles. Set
`maku.broker.database.caSecret` and list `databaseCA` for the CA.

### AWS Secrets Manager

```yaml
externalSecrets:
  enabled: true
  storeRef: {kind: ClusterSecretStore, name: aws-secrets-manager}
  secrets:
    databaseBroker:
      data:
        - {secretKey: uri, remoteRef: {key: prod/maku/rooms-broker-dsn}}
    gatewayProvider.anthropic:
      data:
        - {secretKey: apiKey, remoteRef: {key: prod/maku/anthropic, property: api_key}}
```
